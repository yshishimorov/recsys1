# Automated Feature Engineering vs Manual RecSys: Исследование для Т-Образования

Репозиторий с решением исследовательского кейса по рекомендательным системам в рамках отбора на программу «Т-Образование».

Проект посвящён исследованию применимости автоматической генерации и отбора признаков (Feature Synthesis & Selection) в сравнении с классическим экспертным конструированием признаков для задачи ранжирования в рекомендательных системах.

---

## 📌 О проекте и мотивация

В индустриальных рекомендательных системах качество ранжирования во многом определяется качеством признакового описания пар «пользователь — объект». Традиционно инженеры формируют признаки вручную: выбирают временные окна (например, 7, 30 или 90 дней), типы агрегаций (сумма, среднее, квантили) и разрезы сущностей (прямые взаимодействия, категории, жанры). 

Однако этот подход сопряжён с ограничениями:
1. **Субъективность выбора параметров**: почему окно именно в 7 дней, а не 10 или 14?
2. **Высокая трудоёмкость**: ручной перебор гипотез требует постоянного участия инженера.
3. **Риск пропуска нетривиальных сигналов**: человек склонен использовать очевидные агрегаты, упуская скрытые зависимости.

**Цель проекта**: разработать воспроизводимый ML-пайплайн без утечек во времени (data leakage) и экспериментально проверить, способен ли автоматический поиск признаков в заданном комбинаторном пространстве конкурировать с сильным бейзлайном на ручных признаках.

## 📊 Данные и постановка задачи

В качестве основы используется открытый датасет взаимодействий онлайн-кинотеатра **KION (МТС)**:
* `interactions.csv` — история просмотров (пользователь, объект, дата, длительность, процент досмотра).
* `users.csv` — демографические характеристики клиентов (возраст, пол, доход, наличие детей).
* `items.csv` — метаданные контента (жанры, тип контента, год выпуска, возрастной ценз).

### Сэмплирование без потери профиля
Для обеспечения скорости итераций и экономии ресурсов выборка сэмплируется по **5 000 случайных пользователей**, при этом сохраняется вся хронологическая история каждого выбранного пользователя. Это предотвращает искажение пользовательских паттернов.

### Формирование таргета
Решается задача бинарной классификации отклика:
$$\text{label} = \begin{cases} 1, & \text{если } \text{watched\_pct} \ge 50\% \\ 0, & \text{если } \text{watched\_pct} < 50\% \end{cases}$$
Предсказания вероятности используются для последующего ранжирования объектов пользователю.

### Корректный Temporal Split (исключение утечек)
Все взаимодействия строго сортируются по временной метке и делятся во времени:
* **Train** (первые 70% времени) — обучение;
* **Validation** (следующие 15% времени) — валидация, ранняя остановка бустинга и отбор признаков;
* **Test** (финальные 15% времени) — итоговая оценка обобщающей способности.

При расчёте признаков для любого среза используется только информация, доступная строго до момента предсказания.

## 🔬 Исследуемые подходы

### 1. Baseline: Экспертный Feature Engineering
Построение набора признаков на основе типовых практик RecSys по фиксированным окнам (7, 30, 90 дней):
* **Признаки пользователя**: активность (число просмотров), средний таргет, средний процент просмотра.
* **Признаки объекта**: популярность контента, средняя конверсия в успешный просмотр.
* **Прямые связи (User-Item)**: число прошлых взаимодействий пары за заданные окна.
* **Косвенные связи (User-Genre)**: частота потребления конкретного жанра пользователем.
* **Категориальные метаданные**: возраст, пол, доход, тип контента, возрастной рейтинг.

### 2. Исследовательский подход: Автоматический синтез и отбор признаков
Вместо ручного выбора строится параметрическое пространство поиска признаков:
* **Ключи группировки ($5$ срезов)**: `user_id`, `item_id`, `(user_id, item_id)`, `(user_id, main_genre)`, `(user_id, content_type)`.
* **Временные окна ($9$ вариантов)**: $1, 3, 7, 14, 30, 60, 90, 180, 365$ дней.
* **Агрегирующие функции ($5$ видов)**: `count`, `mean`, `std`, `max`, `min`.
* **Целевые числовые поля**: `watched_pct`, `total_dur`.

Синтезируется пул из сотен кандидатных признаков. Для борьбы с мультиколлинеарностью и переобучением применяется двухэтапный отбор:
1. Оценка информативности признаков на валидации с помощью быстрого легковесного дерева (LightGBM).
2. Отбор **топ-50 наиболее значимых признаков** (Top-N Feature Importance).
3. Обучение финального классификатора CatBoost на отобранном подмножестве.

## 📈 Метрики оценки

Модели сравниваются на одинаковой тестовой выборке по двум группам метрик:

1. **Метрики классификации**:
   * **ROC-AUC** — способность модели ранжировать положительные примеры выше отрицательных.
   * **LogLoss** — калибровка предсказанных вероятностей.
2. **Метрики ранжирования (по пользователям)**:
   * **NDCG@5, NDCG@10, NDCG@20** — качество ранжирования с учётом дисконтирования позиции.
   * **Recall@5, Recall@10, Recall@20** — полнота нахождения релевантных объектов в топе рекомендаций.

## 🚀 Инструкция по воспроизведению

### 1. Клонирование и установка окружения
```bash
git clone https://github.com/<username>/recsys-feature-engineering.git
cd recsys-feature-engineering
pip install -r requirements.txt
```

### 2. Загрузка данных
```bash
python download_data.py
```
> *Примечание*: Если прямой доступ к репозиторию ограничен, скачайте `interactions.csv`, `users.csv`, `items.csv` из [KION Dataset](https://github.com/irsafilo/KION_DATASET) и положите их в каталог `data/raw/`.

### 3. Подготовка данных и разбиение
```bash
python prepare_data.py
```
Скрипт выделит 5 000 пользователей, сформирует бинарный таргет и сохранит выборки `train.parquet`, `val.parquet`, `test.parquet`.

### 4. Запуск полного цикла обучения и сравнения
```bash
python run_pipeline.py
```
Команда выполнит:
1. Построение ручных признаков и обучение CatBoost Baseline.
2. Синтез сотен автоматических признаков, отбор топ-50 и обучение модели Auto-Features.
3. Оценку обеих моделей на отложенном тесте и сохранение сводной таблицы в `results/comparison.csv`.

### 5. Визуализация результатов (опционально)
```bash
python visualize.py
```
Сохраняет сравнительные гистограммы метрик и графики Feature Importance в `results/`.

## 💡 Выводы и анализ

1. **Качество и обобщающая способность**: Автоматический синтез признаков позволяет покрыть нетривиальные временные горизонты (1, 3, 14, 180 дней), которые часто упускаются при ручном проектировании. Наличие коротких (1–3 дня) и средних (14 дней) окон даёт бустингу дополнительный сигнал о сиюминутных трендах и текущей сессии пользователя.
2. **Баланс вычислительной сложности**: Генерация широкой сетки признаков требует больше времени на предобработку, однако этап отбора по Feature Importance через LightGBM эффективно фильтрует шумовые признаки, сохраняя сопоставимую с бейзлайном скорость инференса.
3. **Отсутствие утечек**: Строгое разделение хронологии взаимодействия гарантирует валидность полученных метрик и переносимость решения в прод-пайплайн.

## 🔭 Перспективные направления

* **Графовые нейросети (GNN)**: Построение гетерогенного графа (пользователи, фильмы, жанры, режиссеры) с обучением эмбеддингов через Link Prediction / Edge Classification для замены явных табличных агрегатов.
* **Последовательные модели (Sequential RecSys)**: Применение трансформерных архитектур над последовательностью взаимодействий с учетом временных дельт между событиями.
* **Генерация фичей через LLM-агентов**: Формулирование признаковых гипотез и синтез SQL/Polars выражений агентом с автоматической валидацией на отложенном фолде.
